# Free game audio packs

Chipboy Studio can fetch a small, curated set of **CC0 game music and sound effects** from public GitHub repositories and turn them into riffs or sampler sounds. The downloader is optional: the core studio, every built-in instrument and every font still work with no connection.

The catalogue lives in [`src/lib/free-packs.ts`](../src/lib/free-packs.ts). The UI lives in [`src/components/FreePackBrowser.tsx`](../src/components/FreePackBrowser.tsx) and appears at the bottom of the Riff library.

## Sources considered and not used

These were checked during the research pass. They are useful sources, but they do not fit the current no-backend, no-bundled-audio design.

| Source | Why it was not used |
| --- | --- |
| [Kenney music jingles](https://kenney.nl/assets/music-jingles) | CC0 and excellent, but the site uses a signed download link generated by JavaScript. It is not a stable direct URL and does not send CORS headers for a browser fetch. |
| [OpenGameArt](https://opengameart.org) | Many CC0 music packs, but the file host does not send `Access-Control-Allow-Origin`. A static app cannot read the bytes without a proxy or bundling the files. |
| [Freesound](https://freesound.org) | Per-file licences and an API key are required. That adds an account, a secret and a rate-limited dependency to an offline app. |
| [FreePD](https://freepd.com) | Public-domain music, but the site itself does not send CORS headers. The GitHub CC0 mirror is used instead. |
| [Chosic](https://chosic.com) | Mixed provenance and no stable direct-file contract. Skipped to keep the audit simple. |

If a future source has a stable HTTPS URL, a clear CC0 or public-domain dedication, and CORS enabled, it can be added to the catalogue.

## How a download works

1. The user opens **Riffs → Free game audio** and picks a pack.
2. **Preview** fetches only that file. Audio is decoded with the Web Audio API; MIDI is parsed into notes.
3. **Add riff** parses a MIDI file, keeps the first bar, and saves a custom riff in `My riffs`.
4. **Add sample** decodes the audio and adds a `SampleAsset` to the Sampler.
5. The file is cached in memory for the current session. The browser may also keep it in its HTTP cache.

There is no server, no account, no analytics and no upload. The app never downloads anything in the background. The download limit is **12 MB per file** so a mobile WebView does not run out of memory on a large track. Requests time out after 30 seconds, and the decoded-audio preview cache is capped at **96 MB** with oldest-first eviction.

The Android build declares `INTERNET` for this feature. The core studio, all built-in sounds and all fonts are bundled and work in airplane mode.

## MIDI import rules

The importer is a small Standard MIDI File reader in [`src/lib/midi.ts`](../src/lib/midi.ts). It supports format 0 and format 1 files with PPQ timing.

- Reads note-on and note-off events, including running status and note-on with velocity 0.
- Reads the time signature meta event. A 4/4 bar is the default.
- Skips General MIDI percussion channel 10, because a melodic riff preset cannot represent a GM drum map.
- Uses the first note as the start of the one-bar window. Notes in later bars are ignored.
- Quantizes starts and durations to 0.25 steps on the 16-step grid.
- Caps a riff at 512 notes, matching the riff schema.
- Lets the user choose the import preset. The default is Coin pulse 25%.

The result is saved through `saveCustomRiff`, so it follows the same 40-riff browser-storage limit as a captured pattern. A downloaded MIDI file is never written to disk.

## Audio import rules

- The browser must be able to decode the format. MP3, OGG and WAV work in current Chrome, Firefox, Safari and Android WebView builds.
- The decoded `AudioBuffer` becomes a `SampleAsset` with `rootMidi: 60`. Change the root note in the Sampler if the sample is pitched differently.
- Loops are marked with the `loop` flag from the catalogue. The Sampler can still change the mode.
- Long tracks are not trimmed automatically. Use the Sampler's crop and slice tools.

## Adding a pack

1. Verify the licence. Use CC0, public domain, or a clear free-use licence that permits redistribution and derivative works. Do not add a pack whose licence requires an attribution screen the app does not have.
2. Verify the direct URL. It must be HTTPS, stable, and return `Access-Control-Allow-Origin: *`. GitHub raw file URLs are the default.
3. Add the pack and its assets to `src/lib/free-packs.ts`. Use a stable `id`, a pack-level `sourceUrl` and `licenseUrl`, and a short description for every asset.
4. Keep each file under 12 MB. Prefer OGG or MP3 for long audio and MIDI for riffs.
5. Run `pnpm test` and `pnpm check`. The catalogue test checks unique IDs, HTTPS URLs, encoded paths, CC0 licences and the size ceiling.
6. Run `corepack pnpm free-packs:check` to verify every URL returns 200, sends CORS headers, and stays under the size ceiling.
7. Update this document and the changelog.

## Legal notes

- **No copyrighted game music is included.** The packs are original CC0 works or public-domain works. Do not add transcriptions or rips of Nintendo, SEGA, Sony, Capcom or other commercial game soundtracks.
- **CC0 does not require attribution.** The app still credits every author and links the source. That is good practice and makes the provenance auditable.
- **Do not add CC-BY assets** until the app has a persistent attribution screen that satisfies the licence. A one-line card is not enough for a share-alike or notice-retention requirement.
- **Do not add fan remixes** even when the uploader labels them free. The underlying composition may still be copyrighted.
- **Keep the source links alive.** If a repository moves, update the catalogue and the test will keep the URL shape honest. A dead URL is a broken button, not a licence problem, but it is still a release blocker.

## Privacy

The downloader makes a request only when the user taps Preview or Add. The request goes to `raw.githubusercontent.com` and contains no project data, no account and no identifier beyond normal HTTP metadata. The app has no backend to receive uploads. See the privacy section in the main [README](../README.md) for the full data-flow statement.
